La **Conexión vía API** integra tus sistemas directamente con la plataforma de Tartini. La página gestiona los **tokens de API** que autentican esas llamadas.

{/* CONFIRMAR: qué operaciones expone hoy la API pública (mensajes, contactos, conversaciones, consulta de datos): no cubierto por el inventario de pantallas ni por la API Reference actual. */}

La página está en **Configurações > Canais > Conexão via API** (Configuraciones > Canales > Conexión vía API) ([talk.saninternet.com/settings/channels/api](https://talk.saninternet.com/settings/channels/api)).

<Note>
  Para la referencia completa de endpoints, autenticación, payloads y códigos de error, consulta la [Referencia de la API](/es/api-reference/introduction).
</Note>

## Cómo funciona

Cada token es una credencial personal de aplicación (no está vinculada a un usuario humano) que autentica solicitudes a la API REST de Tartini. Creas tantos tokens como necesites, uno por integración, por ejemplo, y revocas individualmente cuando alguna clave se filtra o un sistema antiguo se desactiva.

La autenticación sigue el estándar **Bearer Token** en el header HTTP:

```http
Authorization: Bearer <seu-token>
```

<Warning>
  El token completo aparece **una única vez**, en el momento de la creación. Después de eso, Tartini muestra solo una versión enmascarada (ej.: `talk_••••••••a1b2`). Si pierdes el token, tendrás que generar uno nuevo.
</Warning>

## Crear un token

<Steps>
  <Step title="Abre el modal de creación">
    Haz clic en **Criar Token** (Crear Token), en el encabezado de la página (o en el botón del estado vacío, antes de que exista algún token).
  </Step>

  <Step title="Completa los datos">
    - **Nome** (Nombre) (obligatorio): identificador corto, ej.: `Integração ERP`.
    - **Descrição** (Descripción) (opcional): texto libre para describir el propósito del token.
  </Step>

  <Step title="Copia el token">
    Después de la creación, un modal muestra el **token completo**. Cópialo y guárdalo en un lugar seguro: por motivos de seguridad, Tartini no volverá a mostrar ese valor.

    <Warning>
      Este es el único momento en que el valor completo queda visible. Al cerrar el modal, Tartini pasa a mostrar solo la versión enmascarada.
    </Warning>
  </Step>
</Steps>

## Ver y gestionar tokens

La página lista todos los tokens creados por la Empresa en tarjetas, con:

| Campo | Descripción |
|-------|-----------|
| **Nome** (Nombre) | Identificador del token. |
| **Ícone de status** (Ícono de estado) | Verde (activo) o rojo (inactivo). |
| **Descrição** (Descripción) | Texto opcional insertado en la creación. |
| **Token** | Valor **enmascarado** (ej.: `talk_••••••••a1b2`). |
| **Último uso** | Fecha y hora de la última solicitud autenticada, o "Nunca" si nunca se usó. |
| **Criado em** (Creado en) | Fecha y hora de la generación. |

### Eliminar un token

Cada tarjeta tiene un botón de papelera (tooltip **Excluir token** / Eliminar token). Al hacer clic se abre una confirmación. Al confirmar, el token se revoca y deja de autenticar llamadas a la API.

{/* CONFIRMAR: código de respuesta HTTP para llamadas hechas con un token ya revocado, y si hay algún tiempo de propagación hasta que la revocación tenga efecto. */}

<Warning>
  En la pantalla, la única acción disponible para un token existente es la eliminación, que no se puede deshacer. Antes de eliminar, asegúrate de que ningún sistema crítico siga usando ese token.
</Warning>

## Buenas prácticas

- **Tokens por integración**: como la eliminación de cada token es independiente, integraciones distintas pueden usar tokens distintos, sin afectar a las demás al eliminar una de ellas.
- **Seguridad del token**: mantén el valor en un lugar seguro y nunca lo compartas, tal como indica el propio aviso de la pantalla.
- **Campo "Último uso"**: ayuda a identificar tokens sin uso reciente al revisar cuáles siguen siendo necesarios.

---

## Quién puede generar tokens

Solo el **Administrador de la Empresa** tiene permiso para crear y revocar tokens de API. Gestores y Agentes no ven la página de Conexión vía API.
