A **Conexão via API** integra seus sistemas diretamente com a plataforma do Tartini. A página gerencia os **tokens de API** que autenticam essas chamadas.

{/* CONFIRMAR: quais operações a API pública expõe hoje (mensagens, contatos, conversas, consulta de dados): não coberto pelo inventário de telas nem pela API Reference atual. */}

A página fica em **Configurações > Canais > Conexão via API** ([talk.saninternet.com/settings/channels/api](https://talk.saninternet.com/settings/channels/api)).

<Note>
  Para a referência completa de endpoints, autenticação, payloads e códigos de erro, veja a [API Reference](/api-reference/introduction).
</Note>

## Como funciona

Cada token é uma credencial pessoal-de-aplicação (não está vinculada a um usuário humano) que autentica requisições à API REST do Tartini. Você cria quantos tokens precisar, um por integração, por exemplo, e revoga individualmente quando alguma chave vaza ou um sistema antigo é desativado.

A autenticação segue o padrão **Bearer Token** no header HTTP:

```http
Authorization: Bearer <seu-token>
```

<Warning>
  O token completo aparece **uma única vez**, no momento da criação. Depois disso, o Tartini mostra apenas uma versão mascarada (ex.: `talk_••••••••a1b2`). Se você perder o token, terá que gerar um novo.
</Warning>

## Criar um token

<Steps>
  <Step title="Abra o modal de criação">
    Clique em **Criar Token**, no cabeçalho da página (ou no botão do estado vazio, antes de existir qualquer token).
  </Step>

  <Step title="Preencha os dados">
    - **Nome** (obrigatório): identificador curto, ex.: `Integração ERP`.
    - **Descrição** (opcional): texto livre para descrever o propósito do token.
  </Step>

  <Step title="Copie o token">
    Após a criação, um modal exibe o **token completo**. Copie e guarde em local seguro: por motivos de segurança, o Tartini não volta a exibir esse valor.

    <Warning>
      Este é o único momento em que o valor completo fica visível. Ao fechar o modal, o Tartini passa a exibir apenas a versão mascarada.
    </Warning>
  </Step>
</Steps>

## Ver e gerenciar tokens

A página lista todos os tokens criados pela Empresa em cards, com:

| Campo | Descrição |
|-------|-----------|
| **Nome** | Identificador do token. |
| **Ícone de status** | Verde (ativo) ou vermelho (inativo). |
| **Descrição** | Texto opcional inserido na criação. |
| **Token** | Valor **mascarado** (ex.: `talk_••••••••a1b2`). |
| **Último uso** | Data e hora da última requisição autenticada, ou "Nunca" se nunca foi usado. |
| **Criado em** | Data e hora da geração. |

### Excluir um token

Cada card tem um botão de lixeira (tooltip **Excluir token**). Clicar abre uma confirmação. Ao confirmar, o token é revogado e deixa de autenticar chamadas à API.

{/* CONFIRMAR: código de resposta HTTP para chamadas feitas com um token já revogado, e se há algum tempo de propagação até a revogação valer. */}

<Warning>
  Na tela, a única ação disponível para um token existente é a exclusão, que não pode ser desfeita. Antes de remover, certifique-se de que nenhum sistema crítico ainda está usando aquele token.
</Warning>

{/* CONFIRMAR: os cards mostram um ícone de status ativo/inativo por token: não está confirmado se um token pode ficar inativo por outro motivo além da exclusão (ex.: expiração). */}

## Boas práticas

- **Tokens por integração**: como a exclusão de cada token é independente, integrações diferentes podem usar tokens diferentes, sem afetar as demais ao remover uma delas.
- **Segurança do token**: mantenha o valor em segurança e nunca o compartilhe, como orienta o próprio aviso da tela.
- **Campo "Último uso"**: ajuda a identificar tokens sem uso recente na hora de revisar quais ainda são necessários.

---

## Quem pode gerar tokens

Apenas o **Administrador da Empresa** tem permissão para criar e revogar tokens de API. Gestores e Atendentes não veem a página de Conexão via API.
